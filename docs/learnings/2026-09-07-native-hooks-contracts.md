# Native hooks: файловая идентичность, установка и диагностика

**Date:** 2026-09-07
**Area:** Native hooks — evaluator, конфигурация хостов, doctor
**Root Cause:** Проверки использовали строковое представление или промежуточное состояние вместо фактического контракта файловой системы, apply_patch и Git.

## What happened

Ревью выявило десять дефектов: обход protect-path через регистр и Add File, отклонение допустимого patch, расширение прав конфигурации и неполный rollback. Установка также могла воссоздать tracked-файл, оставить локальные файлы видимыми Git или остановиться из-за чужого symlink при выключенных hooks. Doctor принимал неверное событие и JSON с посторонним содержимым за корректную установку.

## Why it happened — Root Cause Analysis

- `EvalSymlinks` разрешает ссылки, но не гарантирует приведение регистра компонентов к именам каталога. Сравнение путей как строк не всегда соответствует идентичности файлов.
- Заголовок `Add File` описывает синтаксис patch, а не гарантирует отсутствие цели. Классификация должна учитывать файловую систему, cwd и предшествующие операции того же patch.
- Грамматика update не принимала пустую строку контекста без префикса, которую допускает инструмент.
- Атомарный rename заменяет также inode и права файла. Writer задавал `0644`, а rollback сохранял только содержимое. Ошибка чтения очередного файла обходила ветки восстановления.
- Принадлежность Git index не зависит от наличия файла в working tree. Правило в `info/exclude` может быть отменено более приоритетным `.gitignore`.
- Проверка безопасности записи запускалась до определения необходимости изменять чужую конфигурацию.
- Doctor сравнивал общую длину списка событий и декодировал лишь первый JSON-объект.

## What I probably didn't know

Распространённое заблуждение — считать нормализованную строку достаточным описанием ресурса. Для файла важны идентичность и права, для установки — фактическое действие настроек, для протокола — точный набор событий и полный входной документ.

## The fundamental knowledge

Проверка должна опираться на тот же контракт, по которому затем действует исполнитель. При нечувствительном к регистру томе разные написания могут обозначать один файл; на другом томе это разные файлы. Поэтому нельзя безусловно приводить все пути к нижнему регистру. Существующие компоненты сопоставляются с реальными именами и файловой идентичностью; новые компоненты разрешаются относительно существующих родителей.

Операции patch оцениваются последовательно. Add поверх существующей цели — update; после удаления или переноса состояние этой цели меняется. При этом синтаксическая валидация тела Add остаётся отдельной от классификации операции для policy.

Если два ещё не существующих пути в одном patch отличаются только регистром, evaluator отклоняет неоднозначную последовательность: до создания у них нет файловой идентичности. В таком patch требуется единое написание пути; автоматическое определение чувствительности тома для этого случая пока не реализовано.

Транзакция из нескольких файлов требует снимка содержимого, существования и прав. Любая ошибка после записи первого файла должна проходить через восстановление. Если цель изменилась посторонним процессом, rollback не должен затирать новое содержимое; ошибка должна назвать невосстановленные пути.

Git определяет игнорирование с учётом приоритетов и negation. Наличие строки исключения не доказывает, что локальный config или журнал скрыт от Git. Проверку следует делегировать Git с предполагаемыми настройками и выполнять до записи конфигураций.

`json.Decoder.Decode` читает одно значение. Для файла с единственным объектом следующий Decode должен вернуть `io.EOF`. Установка событий проверяется отдельно: ожидаемое число `PreToolUse` и ожидаемое число `Stop`.

Изменённые контракты используются `Evaluate` для PreToolUse и Stop, `Generate`/`GenerateDryRun` для планирования и установки, `doctor.Check` для диагностики. Форматы native JSON и публичные команды остаются совместимыми; меняются решения для дефектных входов и сохранение файловых прав. Регрессионные тесты проверяют оба адаптера и отказ без частичной установки.

Итог impact-check: новых подтверждённых регрессий не обнаружено. Изменены три production-файла (`internal/hooks/paths.go`, `internal/hooks/evaluate.go`, `internal/harness/native_hooks.go`), вызовы parser в существующем тесте и четыре новых файла регрессионных тестов.

Проверки исправления: `go test ./...`, `go vet ./...`, `harnest verify --changed`, `git diff --check`. Отдельный CLI-smoke подтвердил неизменность файлов после dry-run, приватные права новых configs, действующие ignores, deny для записи через другой регистр в обоих адаптерах и отказ doctor при постороннем тексте после JSON. Проверка разных существующих файлов на case-sensitive томе добавлена, но пропущена на текущем macOS томе. Реальные Claude Code/Codex host sessions заново не запускались.

## Key takeaway — Prevention checklist

- Проверять файловые ограничения на томах с разной чувствительностью к регистру, включая symlink, root/cwd и новые дочерние пути.
- Проверять последовательности операций, а не только одиночные заголовки patch.
- Сохранять права вместе с содержимым; проверять rollback при ошибке чтения, записи и конфликте состояния.
- Проверять index и фактическое игнорирование Git, включая пользовательские negation и worktree.
- Проверять полный JSON и точные типы событий; иметь положительные проверки допустимых входов рядом с отрицательными.
