# Project Rules Builder

Создай минимальные правила и работающие хуки под выбранный провайдер.

## Выбор провайдера

1. До записи спроси: «Для какого провайдера добавить правила и хуки: Codex, Claude Code или оба?» Явный выбор в текущем запросе или предыдущем ответе уже достаточен; не определяй цель по агенту, который выполняет скилл. Пока ответ неизвестен, можно читать проект, но не писать provider-specific файлы.
2. Работай с native-файлами выбранного провайдера. Если запрошены только правила или только хуки, сохрани этот scope.

## Анализ правил

Этот раздел можно использовать отдельно: результат — кандидаты, без записи и активации.

1. Прочитай существующие root/nested instructions, rules, настройки hooks, манифесты и только относящиеся к задаче исходники/тесты. Используй architecture docs, если они есть; их отсутствие не блокирует работу и не запускает bootstrap.
2. Подтверди каждый кандидат путём, символом, тестом, конфигурацией, документацией или конкретным ответом пользователя. Удали дубли и общие советы, которые модель уже знает.
3. Определи применимость: пути, операции и проверяемое условие. Не расширяй ограничение на весь проект без основания. Семантические требования оставляй инструкциями/review; не выдавай эвристику за гарантию.
4. Раздели обязательную инструкцию, предпочтение, запрет до операции и проверку после операции. Для механического запрета укажи реально покрываемые инструменты; `Stop` не предотвращает уже выполненное изменение.
5. Покажи компактную таблицу: правило, scope, evidence, файл назначения, enforcement/event и ограничения. Запрошенные пользователем точные правила уже согласованы. Новые ограничения, выведенные из наблюдений, остаются кандидатами до его решения.

## Реализация

1. Загружай только нужные справки: [Codex](references/codex.md), [Claude Code](references/claude-code.md); для обоих — обе. Перед генерацией сверяй события, поля и способы регистрации с **актуальной официальной документацией**, указанной в справке, и версией целевого CLI/хоста. Не полагайся только на поисковый сниппет или память. Если документация недоступна, используй проверенную документацию установленной версии; иначе оставь hooks черновиком и назови неподтверждённый контракт.
2. Правила Claude Code записывай в `.claude/rules/<topic>.md`, общие инструкции — в `CLAUDE.md` при необходимости. Для Codex используй `AGENTS.md` с явной применимостью; не копируй Claude `paths` frontmatter как будто Codex понимает его. Оба провайдера должны получить один согласованный смысл, но собственные форматы.
3. Если нужен hook, прочитай [общий workflow hooks](references/native-hooks.md). Переиспользуй проверку проекта; иначе напиши минимальный handler на уже доступном runtime. Не добавляй новый policy engine или зависимости ради обёртки над одной командой.
4. До подключения подготовь точный diff: файлы, event/matcher, исходник handler, команду, cwd, timeout и побочные эффекты. Выполни разрешённые локальные проверки. Если пользователь уже поручил подключить эти правила/hooks, продолжай; отдельно спроси только о новых ограничениях или действиях за пределами запроса. Штатный trust провайдера не обходи.
5. Меняй только согласованные записи; сохраняй пользовательский текст, чужие hooks и остальные ключи настроек. Для файлов или блоков, управляемых внешним генератором, меняй источник, а не результат генерации; не дублируй его hooks. Повторный запуск должен обновлять существующий handler, а удаление — убирать только его регистрацию и принадлежащие ему файлы. Невалидный JSON/TOML не заменяй пустым конфигом.

## Проверка и результат

- Проверь синтаксис файлов и применимость правил. Для hooks выполни проверки из общей справки; оставь маленький воспроизводимый тест рядом с handler.
- Проверь загрузку правил и реальное срабатывание в каждом доступном целевом хосте. Отличай `файлы созданы`, `handler проверен напрямую`, `требуется trust/reload`, `подтверждён вызов хостом`. Если хост недоступен, заверши доступные проверки и явно отметь непроверенный smoke.
- Сообщи выбранных провайдеров, изменённые пути, pass/fail проверок и реальные ограничения покрытия.
